
# MailFlow

MailFlow — веб-приложение для управления email-рассылками, разработанное на Django в рамках курсовой работы №4 образовательной платформы Skypro.

Приложение позволяет создавать списки получателей, управлять письмами, настраивать рассылки, отправлять сообщения и анализировать результаты отправки.

## Возможности

### Управление получателями

- Добавление получателей с email, Ф. И. О. и комментарием.
- Просмотр списка получателей.
- Редактирование и удаление получателей.
- Разграничение доступа по владельцу.

### Управление сообщениями

- Создание писем с темой и текстом.
- Просмотр, редактирование и удаление сообщений.
- Использование созданных сообщений в рассылках.
- Доступ пользователя только к собственным сообщениям.

### Управление рассылками

- Создание рассылок с указанием времени начала и окончания.
- Выбор сообщения и получателей.
- Просмотр, редактирование и удаление рассылок.
- Ручной запуск отправки.
- Проверка допустимого периода отправки.
- Запрет отправки отключённых рассылок.
- Сохранение результатов попыток отправки.

### Пользователи и авторизация

- Регистрация пользователей.
- Подтверждение email.
- Вход и выход из системы.
- Восстановление пароля.
- Разграничение доступа к данным.

### Возможности менеджера

Для пользователей группы «Менеджеры» предусмотрена отдельная панель управления.

Менеджер может:

- Просматривать пользователей сервиса.
- Просматривать получателей и рассылки.
- Блокировать пользователей.
- Отключать рассылки.

Менеджер не получает права произвольно изменять чужие рассылки.

### Статистика

Приложение предоставляет статистику по рассылкам и попыткам отправки:

- Общее количество рассылок.
- Количество попыток отправки.
- Количество успешных попыток.
- Количество неудачных попыток.

### Кеширование

Реализованы два вида кеширования:

1. Серверное кеширование статистики главной страницы средствами Django.
2. Клиентское кеширование статических файлов с помощью WhiteNoise и HTTP-заголовков Cache-Control.

Серверное кеширование использует LocMemCache с ограниченным временем хранения данных.

## Установка и запуск

### 1. Клонирование репозитория

```bash
git clone git@github.com:oxtishina-svg/Coursovaya_4.git
cd Coursovaya_4
```

Для клонирования по SSH требуется настроенный SSH-ключ GitHub.

### 2. Установка зависимостей

Для управления зависимостями используется Poetry.

Установите Python 3.12 и Poetry.

Затем выполните:

```bash
poetry install
```

Команда установит зависимости проекта из `pyproject.toml` и `poetry.lock`.

### 3. Настройка PostgreSQL

Установите и запустите PostgreSQL.

Создайте базу данных:

```sql
CREATE DATABASE coursovaya_4;
```

По умолчанию приложение использует следующие параметры подключения:

| Параметр | Значение |
|---|---|
| База данных | coursovaya_4 |
| Пользователь | postgres |
| Хост | localhost |
| Порт | 5432 |

При необходимости укажите собственные параметры подключения в `.env`.

### 4. Настройка переменных окружения

В корне проекта создайте файл `.env`:

```dotenv
SECRET_KEY=replace-with-your-own-secret-key
DEBUG=True
ALLOWED_HOSTS=127.0.0.1,localhost

DB_NAME=coursovaya_4
DB_USER=postgres
DB_PASSWORD=your_postgresql_password
DB_HOST=localhost
DB_PORT=5432

DEFAULT_FROM_EMAIL=noreply@example.com
```

Замените `SECRET_KEY` и `DB_PASSWORD` собственными значениями.

Файл `.env` содержит конфиденциальные данные и не должен публиковаться в репозитории.

### 5. Применение миграций

```bash
poetry run python manage.py migrate
```

### 6. Создание администратора

```bash
poetry run python manage.py createsuperuser
```

Следуйте инструкциям в терминале.

Панель администратора доступна по адресу:

http://127.0.0.1:8000/admin/

### 7. Подготовка статических файлов

```bash
poetry run python manage.py collectstatic --noinput
```

Статические файлы обрабатываются с помощью WhiteNoise.

### 8. Запуск сервера

```bash
poetry run python manage.py runserver --nostatic
```

Приложение будет доступно по адресу:

http://127.0.0.1:8000/

Параметр `--nostatic` позволяет использовать WhiteNoise для обслуживания статических файлов во время локальной разработки.

Для предоставления пользователю полномочий менеджера:

Панель менеджера доступна по адресу:

http://127.0.0.1:8000/manager/

## Отправка писем

Для отправки сообщений используется стандартный механизм Django `send_mail`.

В текущей конфигурации применяется:

```python
EMAIL_BACKEND = "django.core.mail.backends.console.EmailBackend"
```

Это означает, что при локальной разработке письма выводятся в терминал, а не отправляются на реальные email-адреса.

Для использования настоящего почтового сервера необходимо отдельно настроить SMTP.

### Порядок отправки рассылки

1. Пользователь создаёт получателей.
2. Создаёт сообщение с темой и текстом.
3. Создаёт рассылку и выбирает получателей.
4. Указывает время начала и окончания рассылки.
5. Запускает отправку в разрешённый период.
6. Приложение сохраняет результаты отправки.

Каждая попытка отправки получает статус:

- `success` — почтовый backend подтвердил отправку.
- `failed` — при отправке произошла ошибка.

Ответ почтового сервера или описание ошибки сохраняется в истории попыток.

## Тестирование

В проекте используются автоматические тесты Django.

Проверяются:

- Модели пользователей, получателей, сообщений и рассылок.
- Валидация периода рассылки.
- Вычисление статуса рассылки.
- Авторизация и ограничения доступа.
- Разграничение данных разных пользователей.
- Полномочия менеджера.
- Статистика рассылок.
- Серверное кеширование.
- Успешная отправка писем.
- Ошибки почтового сервера.
- Частично успешная отправка.
- Запрет отправки отключённых рассылок.
- Запрет отправки вне установленного периода.
- Работа тестового почтового backend.

Для запуска всех тестов:

```bash
poetry run python manage.py test
```

Для запуска тестов сервиса отправки:

```bash
poetry run python manage.py test mailings.test_services
```

Тесты Django выполняются в отдельной тестовой базе данных.

## Особенности реализации

- Используется собственная модель пользователя на основе `AbstractUser`.
- Данные пользователей связаны с владельцами через ForeignKey.
- Для получателей рассылки используется ManyToManyField.
- Для сохранения результатов отправки применяется модель `MailingAttempt`.
- Сервис отправки вынесен в отдельный модуль `mailings/services.py`.
- Статистика реализована в отдельном представлении.
- Для повышения производительности используются серверное и клиентское кеширование.
- Пароли базы данных и секретный ключ Django загружаются из переменных окружения.
